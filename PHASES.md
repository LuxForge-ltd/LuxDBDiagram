## Handoff Notes

- Checks before each pull request: `npm run lint`, `npx vitest run`, `npm run build`, run on joyeuse.

- GAP checks: `LUXDB_GAP_SCHEMA_DIR="L:/LuxForge/Grassroots Admin Portal/docs/architecture/schema" npx vitest run src/lib/areas`. On 2026-11-24 the GAP domain files had two broken references, reported to the operator: `finances.dbml` line 78 refers to `match_team_players` (the table is `match_team_player`), and `roles_groups.dbml` line 23 refers to `resource_groups`, which only `gap_combined.dbml` defines.
- Phase 05 notes: the per-Area Float filter (All / Outgoing) was added within the approved Float phase after the GAP test showed `users` in an Area brings 55 single-row Floats (every table's `updated_by`). The default was All at first; the operator chose Outgoing as the default on 2026-11-24 (Phase 07).
- Phase 13 notes, release of 0.0.12 to OpenRail (2026-11-25; image built, run locally and pushed from joyeuse, OpenRail CLI on VM 105): image `ghcr.io/luxforge-ltd/luxdbdiagram:0.0.12`, digest `sha256:5aded739adcb4ac4b747b8297849d8e02600c7e387b55201f1ade524cfb79eaf`. That change deployed, but reused the active deployment's 0.0.8 image (digest `sha256:33e4d5c4...`) and dropped the pending 0.0.12 one, although the service showed the 0.0.12 tag. Setting `source.image` to the digest form made OpenRail fetch 0.0.12, and it went online in about ten seconds; the digest stays as the service's image. Checks: the 0.0.12 replica and `web.internal` (four requests, after the old replica drained) answered with the title "LuxForge Database Diagrams built on ChartDB" and both ChartDB flags `"true"` in `/config.js`; anonymous requests to `/`, `/config.js` and a deep link at `luxdbdiagram.luxforge.dev` answered 302 to the Access login. Not checked by the agent: the signed-in page (the browser pane has no Access session); the nginx log shows Edge loading the site through the tunnel on 2026-11-24 at 20:25 UTC, so sign-in through Access works. - Phase 12 notes: a diagram can be saved as one DBML file per Area (`src/lib/areas/area-files.ts`), with `unassigned.dbml` for tables in no Area and `luxdbdiag.areas.dbml` for the Area blocks; Edge and Chrome write into a picked folder after a confirmation, other browsers download the files. The DBML panel can show any Area's file read-only. ChartDB's exporter prefixes Ref names with their position (and names unnamed relationships at random), so the same relationship came out differently in each file and the GAP round trip failed with "References with same endpoints exist"; relationships are now given fixed names and the prefix is removed.
